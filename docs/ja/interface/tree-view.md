# キーのツリービュー

LSDEインターフェースは、プロジェクトのすべての翻訳キーを明確かつ構造化された方法で表示します。キーの管理を簡素化するために設計されており、インポートされたキーであろうと新しく作成されたキーであろうと、自動的に最適化された内部形式に適合させ、その後、プロジェクト固有の形式で出力することで、完璧な互換性と統合を保証します。

::: tip メモ
そのため、`.lsde` プロジェクトファイルを完全に共有し、復元することができます。
:::

`name_space.folderA.folderB.folderC.fileABC` の例を考えてみましょう。
- キーのパスは、ドットを区切り文字として階層的に構造化されています。i18nextの規約と同様のこの慣習により、各キーの場所とフォルダのナビゲーションと特定が容易になります。i18nextはデフォルトで `name_space:folderA.folderB.folderC.fileABC` を使用することに注意してください。
- 各パスの最初のセグメント（最初のドットの前）は、ネームスペースを定義します。このネームスペースは、ツリー構造内で**不変**であると強調することが重要です。

::: tip メモ
ネームスペースを変更するには、言語管理専用のインターフェースを使用する必要があります。この集中型アプローチにより、翻訳の整合性が保証されます。
:::

それでは、キーのツリー構造インターフェースのさまざまなセクションと機能を詳しく見ていきましょう。

## ヘッダーアクション {#header-actions}
1. **孤立したキーの表示/非表示**
このオプションは、翻訳のクリーンさと関連性を維持するために不可欠です。ツリー構造には存在するが、外部プロジェクトのソースコードには存在しないキーをすばやく特定でき、古くなったキーや未使用のキーを検出して、潜在的なクリーンアップや再配置を容易にします。
2. **不完全なキーの表示/非表示**
この機能は、1つ以上の言語で翻訳が欠落しているすべてのキーを強調表示します。

::: tip メモ
**重要事項：** LSDEのキースキャナーは、エディターウィンドウで有効になっている言語のみを分析します。無効になっている言語は分析プロセスから除外され、アクティブな言語の検証に集中できます。
:::

3. **ファイルまたはフォルダの作成**
コンテキストメニュー（右クリック）に加えて、この機能を使用すると、新しいキーを手動で作成したり、ツリー構造を積極的に整理したりできます。LSDEは「内部」フォルダの作成をサポートしており、将来の翻訳のために空のフォルダを作成するなど、キーを論理的に構造化する機能を提供します。これらの操作は、直感的で段階的にガイドしてくれるインタラクティブなウィンドウを介して実行されます。

<DocImage src="/doc/lsde/doc-lsde-ui-createfolder.webp" left />

4. **ネームスペースフィールド**
このフィールドには、新しいキーまたは新しいフォルダが作成されるネームスペースが表示され、既存の階層への正しい挿入が保証されます。
5. **キーパス**
この場所は、キーの完全なパスを入力するために予約されています。システムはリアルタイムでアシスタンスを提供し、パスがフォーマットルールまたは一意性のルールに従っていない場合に即座に警告を発するため、エラーを回避できます。
6. **選択項目の移動**
新しいフォルダを作成する際に特に役立つこのオプションは、ツリー構造から選択した要素を新しいディレクトリに同時に転送することを可能にします。これにより、ワークフローが最適化され、キーの再編成が容易になります。
7. **進行中のタスクを持つキーの表示/非表示**
この機能を有効にすると、アクティブなタスクに関連付けられているキーや、チームメンバーによる検証待ちのキーをすばやく視覚化できます。これは、翻訳の進捗状況を追跡し、プロジェクトを共同で管理するための貴重な資産です。
8. **フォルダの展開/折りたたみ**
このボタンは、ツリー構造で2つの便利なナビゲーションモードを提供します。
- すべてのフォルダを展開して、包括的な概要を表示します。
- または、フォルダを「アクティブな選択項目まで」折りたたんで、気を散らすことなく特定のセクションに集中します。
