# 음성 관리

이 모듈은 게임 및 내러티브 프로젝트에 음성 내레이션을 통합하는 기능을 관리할 수 있도록 합니다.
프로젝트의 각 키에 대해 해당 음성 버전을 생성하고 연결할 수 있습니다.
이 페이지에 더해 [여기에서 전체 가이드](/ko/features/voice)를 찾을 수 있습니다.

---

## 작동 방식 {#how-it-works}
LSDE는 `SAD`와 `MAD`로 약칭되는 두 가지 접근 방식을 지원합니다.
1. **SAD : "단일 배우 대화"**
이 패러다임에서는 각 대화 키에 특정 화자를 메타데이터를 통해 수동으로 연결할 수 있습니다.

::: tip 참고
SAD 모드는 주로 키당 한 명의 배우를 위해 설계되었지만, 예를 들어 다양한 억양이나 목소리가 필요한 일반적인 메시지의 경우 메타데이터를 통해 여러 음성 프로필을 동일한 키에 연결할 수 있습니다.
:::
**SAD** 모드에서 두 개의 개별 키로 관리되는 대화의 예시:
```text
salut ca va ?
```
```text
oui ca va super
```
2. **MAD : "다중 배우 대화"**
이 패러다임에서는 여러 화자가 동일한 대화 키 내에서 참여할 수 있습니다.
그들의 대사는 텍스트를 분할하는 특정 태그로 식별됩니다.
대사 순서는 순차적입니다.
캐릭터 ID와 연결된 텍스트를 추출하려면 정규 표현식 (regex)을 정의해야 합니다.

::: tip 참고
일부 복잡한 프로젝트에서는 여러 대화를 단일 키로 그룹화하고 게임 엔진에서 직접 후처리 단계에서 분리를 관리하는 것이 현명할 수 있습니다.
:::
**MAD** 대화의 예시:

<DocImage src="/doc/lsde/doc-lsde-features-howtorendering-0-animate.webm" />

```text
{lia} salut ca va ?
{boo} oui ca va super
{lia} Ho !
{boo} quoi !? pourquoi cette tete ?
{lia} ...
{sam} ... hey vous 2 !
```

::: tip 참고
이 방법은 관리해야 할 키의 수를 크게 줄여줍니다.
:::
위 예시에서 각 대사마다 고유한 키가 있고 10개 언어로 번역될 경우, 이는 60개 이상의 키를 의미합니다.
이와 같은 수백 개의 상호작용을 포함하는 RPG의 경우, 각 개입을 개별적으로 관리하는 것은 빠르게 감당하기 어려워질 것입니다.

## 전제 조건 {#prerequisites}
음성을 생성하려면 [ElevenLabs](https://elevenlabs.io) 계정 및 API 키가 있어야 합니다.

::: tip 참고
ElevenLabs는 월별 크레딧 할당량과 함께 무료 API 키를 제공하여 해당 기술을 테스트할 수 있도록 합니다.
:::

## 인터페이스 {#interface}
인터페이스에는 언어 목록, 캐릭터 프로필, 음성 생성 도구 및 생성된 음성 기록이 표시됩니다.
0. **기록**
선택한 키에 대해 생성된 모든 오디오 인스턴스 목록.
1. **언어 컨테이너**
이 탭들은 언어별로 캐릭터를 그룹화합니다.
2. **화자 컨테이너**
음성 내레이션을 할당할 수 있는 엔티티(캐릭터) 목록입니다. \\MAD\\ 모드에서는 이들의 순서가 원본 텍스트에 나타나는 순서와 일치합니다.
3. **텍스트**
생성된 음성 내레이션의 기반이 되는 캡처된 텍스트입니다. 원본 텍스트를 변경하지 않고 구두점을 수정하거나 감정 지표를 추가하여 음성에 영향을 주는 것이 좋습니다. 원본 텍스트가 수정되면 경고가 표시됩니다.
4. **향상**
이 버튼은 키의 메타데이터에 정의된 캐릭터의 성격과 컨텍스트를 기반으로 음성 내레이션에 사용될 텍스트를 개선할 수 있습니다.

::: tip 참고
이 기능은 ElevenLabs의 V3 모델에서만 사용할 수 있습니다.
:::
5. **생성기**
이 버튼은 음성을 생성하여 기록에 추가합니다.
6. **초기화**
이 버튼은 텍스트에 대한 변경 사항을 취소하고 원래 캡처된 버전으로 복원합니다.
7. **음성 확인**
음성을 확인할 수 있습니다.
확인된 음성은 기록과 별도로 보관되며 프로젝트 저장 시 정의된 기준에 따라 내보내집니다.

::: tip 참고
동일한 텍스트와 동일한 캐릭터에 대해 여러 음성을 확인할 수 있습니다.
:::
그러면 파일 이름이 자동으로 증분됩니다.
이는 예를 들어 무작위 시드(random seeds)를 사용하는 게임 엔진에서 음성에 미묘한 차이를 주기 위해 유용할 수 있습니다.
8. **생성 서명**
생성 시 사용되는 이 정보는 각 음성의 출처를 추적하고 이해하는 서명 역할을 합니다.

::: tip 참고
예를 들어, 새 캐릭터를 추가하거나 원본 텍스트에서 캐릭터를 이동하더라도 기존 음성을 해당 엔티티에 다시 할당할 수 있습니다.
:::
9. **오디오 플레이어**
음성 재생을 시작하고 피치를 시각화하여 원하는 전반적인 분위기와 비교할 수 있습니다.

## 음성 생성 {#create-voices}
### SAD 사용 {#with-sad}
프로젝트 설정에서 하나 이상의 음성 프로필을 구성하고 음성 관리자를 활성화해야 합니다.
키와 관련된 배우(또는 엔티티) 및 해당 음성 프로필 구성은 메타데이터 창에서 이루어집니다.
### MAD 사용 {#with-mad}
프로젝트 설정에서 하나 이상의 음성 프로필을 구성하고 음성 관리자를 활성화해야 합니다.
그런 다음 *MAD* 모드를 활성화하고 정규 표현식 *(regex)*을 작성합니다.
이는 두 개의 필수 그룹, 즉 배우의 식별자와 해당 텍스트를 캡처해야 합니다.
음성 연결 설정에서 이 캡처 그룹의 인덱스를 정의합니다.

## 문제 해결 {#fix-issues}
텍스트를 확정하기 전에 음성을 생성하는 것은 피해야 할 작업입니다.
그러나 이런 상황이 발생하더라도 LSDE는 음성을 수정하고 재정리할 수 있는 도구를 제공하여 모든 것을 다시 할 필요가 없도록 합니다.
음성이 생성된 후 대화 텍스트를 수정하면 해당 서명이 호환되지 않게 되며, 다시 확인하도록 요청받을 것입니다.
**MAD** 모드에서 캐릭터를 이동, 추가 또는 삭제하는 경우, 이미 생성된 음성 인스턴스도 다시 할당해야 합니다.

::: tip 참고
재할당은 프로젝트의 기본 언어로 수행됩니다. 다른 언어는 원본 서명 덕분에 자동으로 재구성됩니다.
:::
