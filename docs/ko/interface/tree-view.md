# 키 트리

LSDE 인터페이스는 프로젝트의 모든 번역 키에 대한 명확하고 구조화된 개요를 제공합니다. 키 관리를 단순화하도록 설계된 이 인터페이스는 가져온 키든 새로 생성된 키든 관계없이 키를 최적화된 내부 형식에 자동으로 적용한 다음, 프로젝트의 특정 형식으로 다시 렌더링하여 완벽한 호환성과 통합을 보장합니다.

::: tip 참고
따라서 `.lsde` 프로젝트 파일을 완전하게 공유하고 복구할 수 있습니다.
:::

`name_space.folderA.folderB.folderC.fileABC` 예시를 들어보겠습니다:
- 키 경로는 점을 구분 기호로 사용하여 계층적으로 구조화됩니다. 이 규칙은 i18next와 유사하며, 각 키의 위치와 폴더를 탐색하고 식별하는 것을 용이하게 합니다. i18next는 기본적으로 `name_space:folderA.folderB.folderC.fileABC`를 사용한다는 점에 유의해야 합니다.
- 각 경로의 첫 번째 세그먼트(첫 번째 점 이전)는 네임스페이스를 정의합니다. 이 네임스페이스는 트리 구조 내에서 **불변**이라는 점을 강조하는 것이 중요합니다.

::: tip 참고
네임스페이스를 변경하려면 언어 관리에 전용된 인터페이스를 사용해야 합니다. 이 중앙 집중식 접근 방식은 번역의 무결성을 보장합니다.
:::

이제 키 트리 인터페이스의 다양한 섹션과 기능을 자세히 살펴보겠습니다.

## 헤더 작업 {#header-actions}
1. **고아 키 표시/숨기기.**
이 옵션은 번역의 깔끔함과 관련성을 유지하는 데 필수적입니다. 이를 통해 트리 구조에는 존재하지만 외부 프로젝트의 소스 코드에는 없는 키를 신속하게 식별할 수 있어, 잠재적인 정리 또는 재배치를 위한 오래되거나 사용되지 않는 키를 쉽게 감지할 수 있습니다.
2. **불완전한 키 표시/숨기기.**
이 기능은 하나 이상의 언어에서 번역이 누락된 모든 키를 강조 표시합니다.

::: tip 참고
**중요 참고:** LSDE의 키 스캐너는 편집기 창에서 활성화된 언어만 분석합니다. 비활성화된 언어는 분석 프로세스에서 제외되어 활성 언어에 대한 확인에 집중할 수 있습니다.
:::

3. **파일 또는 폴더 생성.**
상황에 맞는 메뉴(마우스 오른쪽 클릭) 외에도 이 기능은 새 키를 수동으로 생성하거나 트리 구조를 선제적으로 구성할 수 있도록 합니다. LSDE는 "내부" 폴더 생성을 지원하여 향후 번역을 위한 빈 폴더 생성을 포함하여 키를 논리적으로 구조화할 수 있는 기능을 제공합니다. 이러한 작업은 단계별로 안내하는 직관적인 대화형 창을 통해 수행됩니다.

<DocImage src="/doc/lsde/doc-lsde-ui-createfolder.webp" left />

4. **네임스페이스 필드.**
이 필드는 새 키 또는 새 폴더가 생성될 네임스페이스를 표시하여 기존 계층 구조에 올바르게 삽입되도록 합니다.
5. **키 경로.**
이 위치는 키의 전체 경로를 입력하기 위한 것입니다. 시스템은 라이브 지원을 제공하며 경로가 서식 또는 고유성 규칙을 준수하지 않는 경우 즉시 경고하여 오류를 피하는 데 도움을 줍니다.
6. **선택 항목 이동.**
새 폴더를 생성할 때 특히 유용하며, 이 옵션을 통해 트리 구조에서 선택된 요소를 새 디렉터리로 동시에 전송할 수 있습니다. 이를 통해 작업 흐름을 최적화하고 키 재구성을 용이하게 합니다.
7. **진행 중인 작업이 있는 키 표시/숨기기.**
이 기능을 활성화하여 활성 작업 또는 팀원 승인 대기 중인 키를 빠르게 시각화할 수 있습니다. 이는 번역 진행 상황 추적 및 프로젝트 공동 관리를 위한 귀중한 자산입니다.
8. **폴더 확장/축소.**
이 버튼은 트리 구조에서 두 가지 편리한 탐색 모드를 제공합니다:
- 전체 폴더를 확장하여 포괄적인 개요를 확인
- 또는 "활성 선택까지" 축소하여 특정 섹션에만 집중하여 작업합니다.
